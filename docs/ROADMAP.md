# Daedalus — Roadmap

Direction, not a work queue. **Do not implement phases automatically.** Each
phase starts when I say it starts. This document is revised as the project
develops; phases and their order are not fixed.

**Current phase:** Phase 1 — Notebook ingestion (`.ipynb`)

Keep this line accurate. It's the fastest way for a new session to know where
things stand.

Scope for the current milestone is settled in `docs/PHASE-0.md`. The intended
end-state product is described in `docs/FEATURES.md`; most of it is deliberately
deferred past this milestone.

---

## Milestone 1 — a measured retrieval spine

The goal is one complete path from a notebook to grounded questions, with
retrieval quality actually measured rather than asserted.

## Phase 0 — Problem definition — complete

Target user, content types, success criteria, and constraints are settled in
`docs/PHASE-0.md`.

## Phase 1 — Notebook ingestion

`.ipynb` only. Markdown cells, code cells, outputs where useful, notebook
metadata where useful. Other formats are later work.

## Phase 2 — Canonical representation

A normalized representation all parsers produce, preserving the
heading → concept → explanation → code → output structure.

## Phase 3 — Storage and chunking

Document and chunk storage. Data model discussion before schema.

## Phase 4 — Reference set and labelling

A hand-labelled set of queries paired with their supporting chunks, plus
groundedness, relevance, and difficulty labels. Roughly ten hours of attention
for 300 items; 150 items is an acceptable smaller target.

This is a phase rather than a task inside another phase because every success
criterion in `docs/PHASE-0.md` depends on it, and because labels generated by
the pipeline cannot be used to evaluate that same pipeline. It depends on
Phase 3 — labelling requires chunks to label — and must precede any reported
retrieval figure.

## Phase 5 — Retrieval

Lexical retrieval, then semantic retrieval, then hybrid *only if the measured
failure modes justify it*. Evaluate each against the Phase 4 reference set
before adding the next.

## Phase 6 — Question generation

Grounded interview questions with references back to source chunks.

## Later milestones

Deferred from Milestone 1 under the two-week constraint. Reasons and open

- Page-image retrieval for figures and diagrams

## Notes / decisions log

Record decisions here as they're made, so a future session doesn't relitigate
them.

### 2026-08-29 — `.ipynb` is the first and only Phase 1 parser

The corpus notebooks are markdown-dominant (510 of 734 cells) and hold the
largest share of prose theory while also carrying code context. Alternatives
considered: PDF first, since the corpus has six PDFs with usable text layers.
Limitation: the notebook parser will not exercise the layout and figure problems
that PDFs and images introduce, so the canonical representation in Phase 2 is
being designed against an easy case.

### 2026-08-29 — All inference runs locally, no paid API

Budget is zero. Embeddings, generation, and judging all run on the local
machine. Alternatives considered: paid API for judging only, measured at roughly
$23 per benchmark cycle. Limitation: a local 8B judge is materially less
reliable than a frontier judge, so judge agreement must itself be measured
against human labels rather than assumed.

### 2026-08-29 — Milestone 1 cut to the retrieval spine

Two weeks at the available hours cannot deliver the feature set in
`docs/FEATURES.md`. Chose a complete measured path over a broader unmeasured
system, following the priority order in `docs/PHASE-0.md`. Limitation: no
interview experience exists at the end of this milestone — only generated
questions with citations.

### 2026-08-29 — `corpus/` stays untracked

Third-party papers and course material, 7.3 MB of binaries. Kept in
`.gitignore`. Limitation: the reference set and any measured result must record
which corpus version produced it, since the corpus is not versioned with the
code.
