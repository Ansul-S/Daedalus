## **1 Introduction to On-Edge Face Detection** 

#### **On-Edge Processing** 

On-edge processing refers to the computation carried out directly inside a hardware device (for example, a CCTV camera or a mobile phone) rather than sending the data to a server. The hardware holds a small processor that is responsible for taking small decisions instantly, such as face detection or face identification. 

A traditional CCTV setup captures video and transmits it through a Network Video Recorder (NVR) to storage, and different software applied on that storage performs face detection, intrusion detection, person tracking, or identification of missing objects. However, many of these tasks do not need a server-based configuration. The CCTV file captures the videos, and a very small processor inside the CCTV is responsible for taking many small decisions. One of the decisions that can be taken on the device is face detection or face identification. 

Such on-edge applications are already available in mobile cameras where the system detects the face region and reports the age of the person, and also where the system detects whether a person is smiling or not. 

### **1.1 Why Feature Descriptors for the Face Region** 

The face region of a human body contains a component called textures. A texture is a pattern (or a certain type of pattern) that repeats several times. If a human face is observed at the micro level, certain types of patterns repeat again and again. The aim of the algorithms discussed here is to identify these patterns, and these patterns are mainly responsible for taking a decision on how to detect the face region in a camera. 

#### **Three Feature Algorithms Covered** 

Three feature descriptor algorithms are covered for face detection: 

- LBP — Local Binary Pattern 

- HOG — Histogram of Oriented Gradients 

- Haar — Haar Features 

Out of these three, Haar is a very popular architecture and is used by many industries, but HOG and LBP also have popularity. 

## **2 Local Binary Pattern (LBP)** 

#### **Local Binary Pattern** 

LBP stands for Local Binary Pattern. It is one of the effective feature descriptors and is mainly responsible for texture description. LBP considers a small rectangular region in the image and identifies or thresholds the neighboring pixels based on the center pixel. 

### **2.1 Pixel Values and Image Bits** 

When any image is considered, the image is represented by a number of pixels. A pixel is one small element in an image and is the unique and composition of many such pixels gives rise to one image. The image has pixel values (also called gray values), and for an 8-bit image these pixel values vary from 0 to 255, that is, there are 256 gray values (2<sup>8</sup> = 256). 

If the image uses multiple bits, the number of pixel values will depend on that. For 9 bits, 2<sup>9</sup> = 512 gray values are possible (0 to 511). Most of the pictures and cameras in daily life (mobile, camcorder,

### **2.2 LBP Algorithm: 3** _×_ **3 Region Threshold** 

LBP considers a 3 _×_ 3 region in an image. At a particular pixel location, a 3 _×_ 3 region is chosen. The center pixel of this region is compared with each of its neighboring pixels: 

Thresholding rule:

### **2.3 Binary-to-Decimal Conversion** 

Once the 8 binary digits are obtained, they are converted into a decimal number. Because there are 8 neighbors, the result is an 8-bit number whose maximum value is 255. 

#### **Clockwise Convention** 

The sequence must start from a fixed starting pixel and proceed in the clockwise direction. Different conventions are possible: one can treat the first pixel as bit 0 or as the highest-order bit. 

Typically the opposite direction convention is used so that bits are labeled 0 _,_ 1 _,_ 2 _, . . . ,_ 7 across the 8 neighbors. 

For the first example, the binary pattern read clockwise gives bits 1 _,_ 1 _,_ 1 _,_ 0 _,_ 1 _,_ 0 _,_ 0 _,_ 0, and the decimal conversion yields: 

2<sup>4</sup> + 2<sup>2</sup> + 2<sup>1</sup> + 2<sup>0</sup> = 16 + 4 + 2 + 1 = 23 

This value 23 is the LBP pattern assigned to that center pixel.

### **2.4 Sliding the Window Across the Image** 

LBP is applied at every pixel location of the image. A center-sliding 3 _×_ 3 window moves across the entire image exactly the same way a convolution operation slides a kernel: at each position, the LBP value is computed for the center pixel. The result is an output image whose pixel values are the LBP codes. 

When applied to a human face, the LBP output highlights the texture quality or texture regions present in the face area. The output accumulates the binary strings available in the image, which is how LBP extracts meaningful features from the face region of a human face (or human object). 

### **2.5 LBP Histogram (Feature Vector)** 

After obtaining the LBP value at every pixel, the next step is to plot its histogram. A histogram calculates the number of occurrences of each value. 

#### LBP histogram: 

- _x_ -axis: LBP values (from 0 to 255 for 8-bit) 

- _y_ -axis: frequency of occurrence of each LBP value 

The histogram records how many times each LBP code appears in the image. 

For example, value 23 may occur many times, value 7 twice, value 5 twice, and so on. The plot of these frequencies is called the LBP histogram or LBP feature vector. 

#### **Why This Matters** 

The LBP histogram is one of the important features used for feature extraction, most commonly for computing the face area in images.

#### **HOG** 

HOG stands for Histogram of Oriented Gradients. It is a famous feature used for feature description in computer vision. This algorithm was initially developed for object detection. HOG is particularly effective when the goal is to find out the shapes and outlines of objects in images.

### **3.1 Stage 1: Preprocessing — Resize to 1:2 Ratio** 

In the preprocessing stage, the original input image is resized so that the number of rows and columns is in a 1 : 2 ratio. 

#### **Resize Example** 

If the original image is 100 _×_ 130, it must be resized to something like 100 _×_ 200 or 50 _×_ 100, so that the row-to-column ratio is 1 : 2.

The gradient of the image is computed. Gradient computation is done on a 3 _×_ 3 block of pixels. The image is treated as a 2D entity with a row index and a column index; equivalently, _x_ and _y_ coordinates, where the horizontal direction is _y_ and the vertical direction is _x_ .

Gradient formulas: 



_Gx_ is the difference between the right and left neighbors of the center, and _Gy_ is the difference between the top and bottom neighbors. 

#### **3.2.1 Handling Border Pixels** 

A border pixel does not have all eight neighbors, so the gradient cannot be computed directly at the edges. Two options are available: 

- Omit border pixels: leave out one row and one column on each side. 

- Zero padding: append one extra row and one extra column on top, bottom, left, and right, with all values set to zero. This is the same zero-padding process used in CNN algorithms. 

Zero padding allows the algorithm to compute gradients for the border pixels as well, although the computation is a kind of pseudo calculation because all the appended values are zero.

### **3.4 Stage 4: The Four Methods of Histogram Computation** 

HOG provides four methods (Method 1 through Method 4) for building the histogram from the gradient data. 

#### **3.4.1 Method 1 — 180-Dimensional Histogram** 

In Method 1, the gradient direction _θx,y_ (in the range 0<sup>_◦_</sup> to 180<sup>_◦_</sup> ) is used directly. This produces a 180-dimensional feature vector because each integer angle value from 0 to 179 gets its own histogram bin. This vector may have many zero components but its ultimate dimension is 180. 

**3.4.2 Method 2 — 9 Bins of 20 Degrees, Angle Only** 

In Method 2, the 0<sup>_◦_</sup> to 180<sup>_◦_</sup> range is divided into 9 bins of 20 degrees each: 



For each bin, the count of pixels whose angle falls into that bin is recorded. The result is a 9-dimensional vector. Method 2 uses the angle only (not the magnitude). 

#### **Why Method 2 Helps** 

Previously Method 1 required a 180-dimensional feature vector for representation. Method 2 uses only 9 dimensions, which is much easier for computation. This is the main advantage: the sparse 180-D vector is converted into a dense 9-D vector. 

**3.4.3 Method 3 — 9 Bins, Sum of Magnitudes** 

Method 3 is like Method 2 but instead of counting the number of pixels in each angular bin, it _adds up the gradient magnitudes_ of the pixels whose angles fall into that bin. Both the gradient magnitude image and the gradient direction image are created from the input. For each of the nine angular bins, the magnitude values of all matching pixels are summed and placed into that bin.

## **4 Haar Features** 

#### **Haar Features** 

The Haar algorithm is a very popular, fast, and efficient method used primarily for detecting

faces. It identifies the face region in any kind of image by computing the difference between a fixed-size window and its nearest neighboring window in the image. 

Haar considers a small fixed-size window and tries to differentiate between that window and its neighboring window. In a face, consecutive windows placed on the face region produce a large difference in gray pixel values, whereas consecutive windows in the hair region or the background produce little difference. Haar tests multiple window positions to find candidate face locations based on these differences. 

### **4.1 Four Haar Feature Types** 

Haar considers four different types of features for detecting the face region: 

|Feature Type|How It Is Computed|
|---|---|
|Edge feature|Two vertically-aligned or horizontally-aligned windows.<br>Take the sum of all pixels in the top region and the sum in<br>the bottom region, and take their diference. The same<br>applies for left vs right.|
|Line feature|Three consecutive windows. Compute (sum of frst) + (sum<br>of third) _−_(sum of the middle), equivalent to white pixel<br>combination minus black pixel. Can be oriented vertically<br>or horizontally.|
|Rectangle feature|Four windows arranged as a 2_×_2 rectangle. Sum the two<br>diagonal blocks and subtract the other two (all white pixels<br>subtracted from all black pixels).|
|Correlation feature|Based on the correlation between regions, completing the<br>set of four feature types considered.|



Essentially, Haar features consider the difference between various regions in the image. 

### **4.2 History of Haar Features** 

The Haar feature was invented in 1909 by a scientist named Haar, which is why it is called the Haar feature. The original work was proposed for some other kind of functional representation. The feature was not used for many years. In the 2000s, this algorithm gained popularity for face recognition applications, and that is why it is now called the Haar feature for face recognition.

## **5 End-to-End Face Detection Pipeline** 

All the algorithms described above share a common structure: given a captured input image, the first task is to identify the face region, and on that region any classifier can be applied to identify whose face it is. In short, the algorithms concentrate on two things: 

1. Identify where the face region is in the input image. 

2. Apply a classifier on that cropped region to identify the person. 

The feature descriptors (LBP, HOG, Haar) must produce very different values for the face region compared to the dress area or the background. The face has a lot of variation, so it is expected that due to this variation a higher or completely different value is obtained for the face region. The descriptor response identifies the cropped region of the face on which detection focuses. 

In deep learning, this cropped region is then fed as input to any CNN algorithm to extract a set of features, and a classifier or search-based approach matches the features against a database of different faces to output the identity of that person. 

## **6 Summary** 

- On-edge processing allows face detection to run directly inside small processors in CCTVs and mobile cameras without a server. 

- LBP thresholds eight neighbors of a center pixel in a 3 _×_ 3 window, forms an 8-bit binary code in clockwise order, and converts it to a decimal value in [0 _,_ 255]. 

- The LBP histogram plots the frequency of each LBP code across the image and forms the LBP feature vector. 

- HOG resizes the image to 1 : 2, computes gradients _Gx_ and _Gy_ , the magnitude � _G_<sup>2</sup> _x_ + _G_<sup>2</sup> _y_ , and the direction tan<sup>_−_1</sup> ( _Gy/Gx_ ). 

- HOG has four histogram computation methods: Method 1 uses the raw 180-D angle histogram; Methods 2–4 use 9 bins of 20 degrees each, with Method 3 summing magnitudes and Method 4 distributing magnitudes proportionately across bins. 

- HOG uses 8 _×_ 8 cells grouped into 16 _×_ 16 blocks (36 values per block), normalized by the L2 norm of the block. A 1 : 2 image with 7 _×_ 14 = 98 blocks produces a 98 _×_ 36 = 3528-dimensional feature vector. 

- Haar features capture regional pixel differences using edge, line, rectangle, and correlation features, supported by the integral image for fast evaluation. 

- All three descriptors produce distinctively different values over the face region, enabling detection of the face before classification.
